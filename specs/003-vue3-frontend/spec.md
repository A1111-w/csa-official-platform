# Feature Specification: Vue 3 前端迁移与 React 分支保留

**Feature Branch**: `codex/vue3-frontend`
**Created**: 2026-11-08
**Status**: Accepted for implementation
**Input**: “将前端改为 vue3 框架（保留 react 的版本，做分支）”“记得上传到 GitHub”。

## User Scenarios & Testing

### User Story 1 - 分支独立和公开访问 (Priority: P1)

维护者可以分别运行 React 和 Vue 版本；访客继续浏览公开内容并完成注册、登录和找回密码。

**Why this priority**: 保留原版本是用户明确要求，认证与公开入口是其他业务的前提。
**Independent Test**: 检查两个分支的框架及提交；通过公开页和认证表单的隔离测试验证接口参数、隐私同意、安全重定向。
**Acceptance Scenarios**:

1. **Given** React Agent/RAG 版本，**When** 创建 Vue 分支，**Then** React 源码和可运行提交仍在独立分支，原有工作区修改不被覆盖。
2. **Given** 未登录访客，**When** 浏览首页、介绍、竞赛、贡献者、资源入口、隐私说明，**Then** 原有 URL 保持有效，加载失败可见且可重试。
3. **Given** 注册页面，**When** 未同意隐私政策或政策版本未加载，**Then** 不能提交；合法注册携带服务器返回的版本。
4. **Given** 登录成功，**When** 跳转来源是外站或登录循环，**Then** 回到站内工作台；会话仍由 Cookie 承载。

### User Story 2 - 业务工作台功能保持 (Priority: P1)

成员与管理员使用 Vue 页面完成资源、竞赛、简历、审核、提案、部门、资料、安全、审计、贡献、导出和轮播维护。

**Why this priority**: 框架迁移不得把既有业务缩减为演示占位页。
**Independent Test**: 逐一对照路由和操作矩阵，验证角色可见性及核心读写请求，构建全部页面。
**Acceptance Scenarios**:

1. **Given** 有效会员会话，**When** 直接打开受限工作台 URL，**Then** 重新核验身份并按原角色等级控制入口。
2. **Given** 管理员，**When** 编辑业务或导出文件，**Then** 使用现有接口、Cookie 与 CSRF，提交后刷新实际数据。
3. **Given** 失效会话或失败接口，**When** 请求返回错误，**Then** 不展示成功数据，显示错误并执行原失效处理。

### User Story 3 - Agent 展示和可教学交付 (Priority: P1)

成员可继续体验问答、引用与轨迹；部长可管理知识库并执行规则评测。教师获得对应 Vue 的运行和学习指引。

**Why this priority**: Agent/RAG 是本项目当前技术展示重点。
**Independent Test**: 使用隔离 API fixture 验证问答、管理权限、评测空维度显示和报告导出；核对教学步骤及真实验证记录。
**Acceptance Scenarios**:

1. **Given** 离线或在线响应，**When** 问答完成，**Then** 显示模式、原问题、引用、调用轨迹和用量，不伪造结果。
2. **Given** 部长，**When** 导入文档或评测数据集，**Then** 限制与既有 API 一致，空知识库不能产生误导性的完整评测样例。
3. **Given** 没有标注的评测维度，**When** 展示报告，**Then** 显示 N/A 而不是 100%。
4. **Given** 教师按文档准备课程，**When** 选择 Vue 版本，**Then** 清楚分支、启动命令、先修知识、可观察成功标准及常见排错步骤。

## Requirements

- **FR-001**: 保留 React 分支 `codex/agent-rag-evaluation` 的快照 `bf1415c`，Vue 在 `codex/vue3-frontend` 独立开发；按用户要求推送这两个分支，不覆盖 main。
- **FR-002**: 新分支前端使用 Vue 3，所有既有公开、认证和工作台页面均有真实可用入口；以源路由清单核对，历史 Next 构建显示的 27 项可能含框架内部页面，不用其数字代替清单。
- **FR-003**: 保留接口路径、请求语义、角色最小等级、Cookie、CSRF、错误码和 traceId 行为；不把 JWT 写入浏览器存储。
- **FR-004**: 保留注册验证、验证码等待、邀请码/普通注册、隐私版本、密码找回与重置验证及站内重定向。
- **FR-005**: 保留既有业务 CRUD、审核、分页/筛选、上传下载和导出能力；危险操作仍需明确用户点击。
- **FR-006**: 保留 Agent 问答、知识库、规则评测、权限、引用轨迹、模式标识和 JSON 导出。
- **FR-007**: 异步界面提供加载、空数据、失败、成功状态；按钮防重复请求，表单具备可访问标签，移动端可阅读操作。
- **FR-008**: 富文本经过净化，动态链接拒绝危险协议；权限最终由未改动的后端执行。
- **FR-009**: 更新 npm lockfile、前端构建、Docker/CI 配置、启动部署文档，提供适合 Vue 的测试与构建命令。
- **FR-010**: 文档和教学指导区分 Vue 与保留的 React 版本；实际未执行的浏览器、真实后端、部署检查不得写成已通过。

## Edge Cases

- 直接刷新深层路由、退出后返回受限页、角色被服务端降级。
- API 不可达、返回空数组、隐私版本读取失败、验证码失败与计时清理。
- 公开 HTML 含脚本/危险链接、登录 redirect 指向外站。
- AI 长请求、空知识库、评测部分失败与无标注维度。

## Success Criteria

- **SC-001**: React 与 Vue 在 GitHub 可分别检出，React 快照与迁移前一致。
- **SC-002**: 原业务路由逐项完成映射，Vue 类型检查、测试和生产构建通过。
- **SC-003**: 认证、角色路由、CSRF、注册隐私版本和 AI 评测展示具有隔离回归证据。
- **SC-004**: 核心浏览器场景完成或明确记录不能执行的环境限制；不能用源码存在宣称验收通过。
- **SC-005**: 文档含实际分支、运行步骤、回退办法、验证结果和剩余限制。

## Assumptions and Scope

本次按已有 Spring Boot API 迁移前端，不变更后端协议、数据库或线上环境。视觉实现可采用 Vue 原生表单布局，无需逐像素复刻 React 动画；交互与业务功能必须保留。用户明确要求框架替换，因此原项目“保持 Next.js”的通用约束在此功能内由该授权覆盖。
