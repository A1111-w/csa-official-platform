# Feature Specification: 协会 Agent、知识检索与评测实验室

**Feature Branch**: `codex/agent-rag-evaluation`

**Created**: 2026-10-31（Asia/Shanghai）

**Status**: Ready for implementation; acceptance remains to be verified

**Input**: 用户希望项目加入 Agent、RAG、Agent 评测，覆盖更多可展示技术点，并参考 GitHub 最新前端分支和开源项目。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查询协会知识并核对依据 (Priority: P1)

会员在工作台提出协会知识问题，获得可核对的检索片段、来源及回答；维护者可以录入和移除知识，限制可见等级。

**Why this priority**: 知识与权限是工具调用和评测的共同基础，用户必须能判断答案来自哪里。

**Independent Test**: 隔离环境录入两份不同可见等级的知识，以普通会员身份查询并检查回答与引用只包含可访问知识；删除后再查。

**Acceptance Scenarios**:

1. **Given** 维护者录入带标题、正文和可见等级的知识，**When** 保存成功并重启应用，**Then** 知识仍可查询且能定位来源。
2. **Given** 问题同时匹配普通知识和受限知识，**When** 普通会员查询，**Then** 结果、引用及回答均不包含受限知识。
3. **Given** 没有可支持问题的资料，**When** 会员查询，**Then** 系统明确说明资料不足，不捏造来源。
4. **Given** 一份已索引知识，**When** 有权限的维护者移除它，**Then** 后续检索不再使用它。

### User Story 2 - 使用可追踪的协会助手 (Priority: P1)

会员通过助手使用知识检索、资源查询和竞赛查询，查看每一步调用、执行状态和耗时，区分本地演示与真实模型回答。

**Why this priority**: 让技术展示具备实际业务价值，解释助手获取信息和停止执行的原因。

**Independent Test**: 分别提出知识、资源和竞赛问题，检查轨迹与来源；以受限身份、未知工具和重复调用验证权限和停止边界。

**Acceptance Scenarios**:

1. **Given** 有查询需求的会员，**When** 助手需要资料或业务信息，**Then** 只能执行获准查询并展示轨迹。
2. **Given** 未配置模型服务，**When** 运行助手，**Then** 界面与结果明确标注本地演示，仍可查看真实检索和查询结果。
3. **Given** 已启用模型服务，**When** 模型请求工具，**Then** 服务端验证工具名和参数，并在有限步数内结束。
4. **Given** 模型失败或超时，**When** 用户运行助手，**Then** 显示可理解的失败，不能伪装为模型成功回答。
5. **Given** 用户无权访问某类信息，**When** 模型或用户要求查询，**Then** 工具仍拒绝访问，不执行业务写入。

### User Story 3 - 复现并比较评测结果 (Priority: P2)

维护者录入问题、预期资料、预期工具和答案关键词，执行评测并检查逐条结果、汇总分数与耗时。

**Why this priority**: 用可重复检查的结果支持检索与工具选择的回归分析。

**Independent Test**: 固定用例运行两次本地评测，检查分数可复现、错误预期产生低分，且普通会员无权运行维护评测。

**Acceptance Scenarios**:

1. **Given** 标注了预期结果的用例，**When** 维护者运行评测，**Then** 获得每条的检索召回、首个相关排名、工具召回、关键词覆盖和耗时。
2. **Given** 某条用例执行失败，**When** 查看报告，**Then** 失败明确记录，不被计为正确结果。
3. **Given** 一份报告，**When** 查看分数说明，**Then** 明确规则指标不代表语义正确性、事实忠实度或人工审核通过。

### Edge Cases

- 空问题、空正文、超长内容、非法可见等级和过多评测用例被拒绝。
- 中文、英文和混合内容可检索；不同长度知识正确切分并回溯原文。
- 知识正文中的指令不能改变工具权限与调用上限。
- 未知工具、非法参数、重复调用和格式错误有有界、可观察的处理。
- 向量服务不可用时不能将关键词结果标记为已完成向量检索。
- 会话失效、权限下降或知识删除后，新请求按当前权限和知识状态执行。
- 缺少某项评测预期时有明确评分约定，不能产生除零或非数值分数。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在登录工作台提供助手、知识维护和评测入口，复用现有账号权限。
- **FR-002**: 维护者 MUST 能录入和移除知识，保存标题、正文、来源、可见等级和创建者，重启后保留。
- **FR-003**: 系统 MUST 在形成上下文前过滤无权知识，并展示可回溯来源。
- **FR-004**: 系统 MUST 支持中文和英文检索，并明确实际采用的检索方式。
- **FR-005**: 助手 MUST 仅调用白名单内知识、资源、竞赛查询；工具执行前独立验证权限与参数。
- **FR-006**: 助手 MUST 对输入长度、结果数量和工具调用次数设置有限上限。
- **FR-007**: 系统 MUST 区分本地演示和真实模型模式，模型失败不得隐藏为成功。
- **FR-008**: 每次运行 MUST 返回运行标识、可展示工具轨迹、来源和耗时，不展示模型内部思维过程或配置秘密。
- **FR-009**: 维护者 MUST 能执行有界评测，检查逐条结果、汇总分数、失败原因和耗时。
- **FR-010**: 评测 MUST 说明检索召回、首个相关排名、工具召回、关键词覆盖的定义和局限，不宣称语义正确或事实忠实。
- **FR-011**: 知识维护与评测 MUST 仅对维护角色开放，会员只能查询授权范围。
- **FR-012**: 交付 MUST 包含隔离验收用例、实际验证结果、使用说明和独立修改记录，保留原工作区修改。
- **FR-013**: 学习安排 MUST 同时审查内容正确性和教学友好性；每课说明前置知识、单一主要目标、操作、可观察结果、常见卡点与讲师提示，区分核心课和需要外部模型的选修，不承诺固定天数内掌握。

### Key Entities

- **Knowledge document**: 协会知识，含标题、正文、来源、可见等级、创建者和时间。
- **Knowledge chunk**: 可检索片段，含文档标识、顺序、内容及可选语义表示。
- **Agent run**: 一次执行，含问题、模式、回答、来源、轨迹、耗时和终止状态。
- **Evaluation case**: 问题及预期文档、工具、关键词与检索范围。
- **Evaluation report**: 逐条结果、聚合指标及评分约定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 固定验收资料中，所有返回片段能定位原文；受限资料在无权用户结果中出现次数为 0。
- **SC-002**: 无模型凭据的演示完成知识、资源、竞赛三类查询，每次结果均显示演示模式。
- **SC-003**: 未知工具、越权和超过预算的测试均在预算内终止，业务写入次数为 0。
- **SC-004**: 固定用例在相同资料和设置下本地运行两次，除耗时和运行标识外分数一致，每条结果可核对预期与实际。
- **SC-005**: 每个故事有可重跑验收、文档与记录；未验证的外部模型和真实部署环境明确列为未验证。

## Assumptions

- 本期目标是技术展示和协会辅助查询，会员可查询，部长及以上维护知识与评测。
- 初期人工录入文本，不做任意网页抓取、PDF/OCR或多模态入库。
- 首批工具只读，不包含改权限、投票、审批、修改资源或代发消息。
- 演示可无模型凭据运行；真实模型和可选语义检索由部署者显式配置。
- 本期不承诺大规模吞吐、持久多轮会话、生产模型效果、语义评判器或第三方观测平台集成。
