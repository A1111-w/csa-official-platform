## 本轮已完成

本轮把此前确认的七个缺口补成可操作流程：

1. 账号删除到期匿名化执行器。
2. 贡献总排行 SQL、缓存和首页展示。
3. 邮件投递崩溃补偿扫描。
4. 上传配额数据库原子预占/释放。
5. 简历 Git 仓库同步前后端闭环。
6. Level 4 审计日志管理页。
7. Level 4 成员筛选、列选择和 Excel 导出页。

各模块使用独立 Git commit，版本与回退顺序见 `docs/feature-completion-learning-guide.md`。

## 仍未完成的真实功能

### 1. 轮播图后台维护页面

公开轮播已经接入首页，后端也有保存和删除接口，但当前没有可视化轮播管理页。管理员仍需通过 API 调试工具维护标题、图片、顺序和启用状态。

### 2. 手动贡献补录页面

`POST /api/sys/contribution/award` 可用，但没有后台表单。自动贡献记录和公开排行已经完整；只有“人工补录积分”仍依赖 API 调试工具。

### 3. 发布环境复验

源码测试和静态构建可以本机执行，但 Docker VHD/EXT4 故障导致当前源码镜像、Playwright、备份恢复和 Trivy 仍需在健康 staging 环境重跑。这个问题属于发布验证阻断，不是业务代码占位。

### 4. 规划阶段模块

支付、RAG/Agent 和多学校租户隔离仍未实现。支付没有被当前产品承诺；RAG/Agent 只有路线文档；多学校 SaaS 本轮按要求只保留 ADR 和迁移方案。

## 不应误报为产品缺陷的项目

- `security-war/SCOPE.md` 中的 TODO 是安全测试授权范围记录，不是线上功能缺口。
- `packed-project.xml` 是历史打包快照，不能代表当前源码。
- `placeholder="..."` 是表单输入提示，不等于未实现。
- `RAG / Agent` 和多学校 SaaS 在当前需求中本来就是路线/ADR 阶段，不应伪装成已交付。

## 建议优先级

1. 先在健康 staging 环境完成 Docker、Playwright、备份恢复和镜像扫描复验。
2. 按运营频率决定是否补轮播管理和手动贡献补录页面。
3. 为新增 Git 同步、审计和导出页面补真实账号 E2E。
4. 多学校能力继续按 ADR 演进，不在当前规模提前拆微服务。

完整部署阻断项和 Docker 验证边界见 `docs/production-readiness/phase-1-verification.md`、`phase-2-verification.md`。
