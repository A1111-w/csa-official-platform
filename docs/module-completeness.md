## 本轮已完成

简历审核从“部长必须提前知道 `resumeId` 并手工调用接口”补成网页可用流程：

```text
成员保存 → 提交审核 → 部长审核队列 → 详情 → 通过/驳回 → 成员看到最终状态
```

关键实现和证据：

- 后端接口：`ResumeController` 的 `/reviews`、`/reviews/{id}`、`/audit`。
- 后端业务：`ResumeService` 的分页批量装配、状态校验、原子审核和审计记录。
- 前端页面：`/dashboard/resume-reviews` 与 `ResumeReviewWorkspace`。
- 数据库：`V3__resume_review_queue_index.sql`。
- 测试：`ResumeServiceTest`、`ResumeControllerAuthorizationTest`、`resume.test.ts`。
- 学习说明：`docs/study-and-demo-guide.md` 的 Day 9 和 `docs/api-map.md` 第 9 节。

## 仍未完成的真实功能

### 1. 贡献排行榜

`ContributionController.getRank()` 当前直接返回空列表，且没有对应前端展示。它不是“暂时没有数据”，而是代码层面的占位实现。实现时需要先确定排行榜口径：总榜、周期榜、按类型榜，以及分数和条数如何混合排序，再补 SQL、缓存、分页和测试。

### 2. 账号最终删除

`POST /api/account/deletion-request` 只会把账号改成 `DELETION_PENDING`、吊销会话并记录审计。最终匿名化/物理删除、审批、备份保留窗口和恢复演练尚未形成可执行流程，因此不能对用户承诺“提交后自动删除”。

### 3. 邮件崩溃补偿

SMTP 已从请求线程移到异步执行器，并有有限重试，但应用在写入投递记录后、发送线程执行前崩溃时，记录可能停在 `PENDING`。需要一个由 `ScheduledJobService` 保护、带幂等键和最大重试次数的补偿扫描任务。

### 4. 上传配额并发一致性

当前上传先 `SUM(size_bytes)`，再写文件和元数据。两个并发上传都可能通过检查。后续应使用数据库锁定/原子账本或专门 usage 表，并补并发集成测试；不能只依赖前端禁用按钮。

### 5. 管理运营页面

审计日志和成员导出已经有后端能力，但没有对应的前端工作台入口。若目标是“所有管理功能都能从网页完成”，这两项还需要页面、权限可见性、下载错误处理和 E2E。

### 6. Git 同步产品路径

当前 `GitService` 只提供被测试过的安全 URL 校验和 clone 方法，没有业务入口调用它。要不要做成“提交简历后自动同步”或“管理员手动同步”必须先定产品语义，再补异步任务、超时、磁盘配额、状态展示和清理策略。

## 不应误报为产品缺陷的项目

- `security-war/SCOPE.md` 中的 TODO 是安全测试授权范围记录，不是线上功能缺口。
- `packed-project.xml` 是历史打包快照，不能代表当前源码。
- `placeholder="..."` 是表单输入提示，不等于未实现。
- `RAG / Agent` 和多学校 SaaS 在当前需求中本来就是路线/ADR 阶段，不应伪装成已交付。

## 建议优先级

1. 先补贡献排行榜，或删除注册页/接口，避免公开 API 长期返回伪成功空数据。
2. 再补邮件 `PENDING` 补偿和上传配额原子计数，这两项直接影响长期稳定性。
3. 按运营需要补审计日志和成员导出页面。
4. 最后决定 Git 同步产品语义，再进入 RAG/Agent 和多租户实现。
