## 本轮已完成

此前确认的缺口现已补成可操作流程：

1. 账号删除到期匿名化执行器。
2. 贡献总排行 SQL、缓存和首页展示。
3. 邮件投递崩溃补偿扫描。
4. 上传配额数据库原子预占/释放。
5. 简历 Git 仓库同步前后端闭环。
6. Level 4 审计日志管理页。
7. Level 4 成员筛选、列选择和 Excel 导出页。
8. Level 4 人工贡献记录页和贡献流水查询。
9. Level 4 首页轮播管理页、停用项列表、图片发布权限和页面级 E2E。

各模块使用独立 Git commit。轮播管理功能提交为 `f295e24`，改动前回退标签为 `before-carousel-management-2026-08-27`；完整版本与回退顺序见 `docs/feature-completion-learning-guide.md`。

## 仍未完成的真实功能

### 1. 发布环境复验

源码测试和静态构建可以本机执行，但 Docker VHD/EXT4 故障仍阻断本地镜像和备份恢复。GitHub Actions `#33010814757` 已在 `fcddab2` 上通过当前源码的镜像构建、Trivy、真实依赖和关键 Playwright E2E；仍需在健康 staging 演练备份恢复。这个问题属于发布环境验证，不是业务代码占位。

### 2. 规划阶段模块

支付、RAG/Agent 和多学校租户隔离仍未实现。支付没有被当前产品承诺；RAG/Agent 只有路线文档；多学校 SaaS 本轮按要求只保留 ADR 和迁移方案。

## 不应误报为产品缺陷的项目

- `security-war/SCOPE.md` 中的 TODO 是安全测试授权范围记录，不是线上功能缺口。
- `packed-project.xml` 是历史打包快照，不能代表当前源码。
- `placeholder="..."` 是表单输入提示，不等于未实现。
- `RAG / Agent` 和多学校 SaaS 在当前需求中本来就是路线/ADR 阶段，不应伪装成已交付。

## 建议优先级

1. 先在健康 staging 环境完成 Docker、Playwright、备份恢复和镜像扫描复验。
2. 为 Git 同步、审计、导出、贡献管理和轮播写操作补真实账号 staging E2E；当前轮播页面已有不依赖真实账号的浏览器级渲染/编辑验收。
3. 多学校能力继续按 ADR 演进，不在当前规模提前拆微服务。

完整部署阻断项和 Docker 验证边界见 `docs/production-readiness/phase-1-verification.md`、`phase-2-verification.md`。
