# Agent 实验台：循序学习与授课安排

这份安排面向已经能登录项目、会看一条请求的学习者，也供讲师备课。先做出可观察的结果，再解释代码；每课只解决一个主要问题。当前入口是 `/dashboard/ai`，实现位于 `modules/ai`。功能边界见 [实验台说明](agent-lab.md)，技术细节按需查 [后端说明](ai-backend.md)，不要求上课前通读全部文档。

## 先选起点，再安排课时

| 起点 | 从哪里开始 | 本轮完成标准 |
| --- | --- | --- |
| 还不能稳定登录或打开工作台 | 先按 [本地开发](local-dev.md) 排好环境，再做原学习指南的单条请求练习 | 能区分页面未启动、未登录和业务请求失败 |
| 会使用页面，但不熟悉 AI | 第 1–4 课 | 独立完成离线检索、权限对照和一次规则评测，讲清局限 |
| 熟悉 Java 请求链，已有可用模型服务 | 完成第 1–4 课后选第 5–6 课 | 分清模型生成、工具选择和向量检索各改变了什么 |

第 1–4 课每课可先预留约 25–40 分钟，第 5–6 课约 40–60 分钟；这是**环境已准备好时的备课估计，不是学完承诺**。可分两次完成一课。安装、下载依赖、排网络问题单独安排，不计入讲解时间。不要为满足“第几天/第几周”压缩动手和答疑。

讲师课前准备：隔离开发环境、可用的 Level 1 和 Level 3 测试账号、`AI_ENABLED=false`、一份干净的小型演示语料。账号由环境维护者准备，不在教材写共享密码。先亲手完成第 1 课；若失败，本节先排环境。已保存的报告可用于解释结构，但要明确它不是本次运行结果。

## 第 1 课：答案究竟从哪里来

- **前置**：能打开 `/dashboard/ai`；本节由 Level 3 账号录入，普通会员可用讲师预置资料。
- **目标**：能指出回答对应的原文，并说明“离线摘录没有调用大模型”。只引入“检索”和“引用”两个词。
- **步骤**：在“知识库”手工录入标题“Java 入门说明”、来源“课堂虚构样例”、正文“Java 入门先学习集合，再练习线程池，最后学习 Spring Boot。”，可见等级选会员；到“问答”问“Java 入门先学什么？”；展开来源和执行轨迹，找出 `search_knowledge`。不要一开始同时演示模型配置。
- **可观察成功结果**：模式为离线摘录，回答能找到上述原文，来源标题和片段 ID 可见；学习者能指着屏幕说明“系统找到什么”和“系统没有做什么”。
- **常见卡点**：看不到添加按钮先检查角色；提示无资料先查是否已保存、当前身份是否可读；页面“待连接”先查服务，不能解释成模型能力差。
- **讲师提示**：先请学习者猜答案会在哪里，再操作验证。暂不要求记 BM25 公式、向量维度或工具协议；把“源文本被引用”和“每句话事实正确”分开说。
- **可选挑战**：在只有本课语料的隔离知识库，问一个完全无关的问题，观察空引用与资料不足提示。先检查语料，不能把已有其它资料造成的命中判成错误。

## 第 2 课：同一个问题，为什么两个人看到不同资料

- **前置**：第 1 课通过；能分清会员 Level 1 与部长 Level 3。两种身份用不同浏览器会话，避免混淆当前账号。
- **目标**：理解“授权决定能查哪些资料”，并把页面操作对应到服务端。只增加“权限过滤”和“服务层”两个概念。
- **步骤**：部长录入“部长培训记录”，正文“本次内部培训地点为演示教室甲。”，来源仍填虚构样例、可见等级选 3；两个账号各问“演示教室甲”，对照资料列表、答案和引用；只读 `AiController` 的运行入口及 `KnowledgeService.search` 的候选 SQL，找到 `min_role_level <= 当前等级` 条件。
- **可观察成功结果**：部长能检索该文档，会员的列表和引用不包含它；学习者能画出“当前身份 → 可读资料 → 检索 → 回答”，而不是把权限说成隐藏按钮。
- **常见卡点**：会员得到其它普通资料的命中并不等于越权，核对的是受限文档 ID 和正文；不要只看是否出现回答。登录切换后确认角色已刷新。
- **讲师提示**：先让学生比较两份结果，再带看一条 SQL；无需本课重讲全部 JWT/CSRF。页面观察用于理解，真正的接口拒绝由 `AiControllerAuthorizationTest` 等测试补证。
- **可选挑战**：在隔离环境删除自己刚建的受限文档，按运行 ID 回读旧运行，解释为什么当前实现会重新检查引用权限并拒绝读取。此接口无专门历史列表页，由讲师通过现有 API 客户端或测试演示。

## 第 3 课：长资料怎么被找到

- **前置**：第 2 课通过；能识别列表和循环即可，不要求机器学习基础。
- **目标**：理解“分块”让资料分段参与检索，“BM25”根据词匹配排序；本课不加入向量算法。
- **步骤**：先看短文档的 1 个分片，再粘贴一份 800–1000 字符的自编学习说明；观察分片数变化，分别查询前后两段的明确关键词；阅读 `KnowledgeService.split` 与 `search`，用一小段文字在纸上演示 700 字符窗口、100 字符重叠的关系。
- **可观察成功结果**：长文档产生多个片段，查询结果可回到原文；学习者能解释重叠是为了减少边界处信息割裂，并知道高排序分数不是正确概率。
- **常见卡点**：相似问题未必词面重合；当前中文使用双字切分，不能保证理解同义词。不要用偶然命中的例子宣称已经有语义理解。多文档同分可能按 ID 排序，不要求每次重建后排名相同。
- **讲师提示**：先用“把长讲义分成可查的小段”讲清用途，再指出 BM25 这个名称。参数与公式留作查阅；本课只要求解释词频、文档长度会影响排序，不要求推导。
- **可选挑战**：在后端目录运行 `.\mvnw.cmd "-Dtest=KnowledgeServiceTest,KnowledgeTransactionTest" test`，读一条分块断言与事务回滚断言，说明它们各证明什么。测试通过不等于真实 MySQL/模型已验收。

## 第 4 课：怎样检查一次回答，而不是只凭感觉

- **前置**：第 1–3 课通过；Level 3 账号；知道 JSON 数组由方括号包围。不会写 JSON 时使用页面“生成示例数据集”，逐字段改，不从空白开始。
- **目标**：先理解“文档召回”和“答案关键词覆盖”两项，能制造一次有解释的失败；其它指标先读说明，不要求一次掌握。
- **步骤**：从知识库复制第 1 课的真实文档 ID；在评测页填入下面数组并替换 ID；运行并导出报告。只把关键词“集合”改为“量子隧穿”，再次运行，比较哪项分数下降；等待限流窗口后，清空关键词数组再运行，观察该维度变为“N/A”。

```json
[
  {
    "question": "Java 入门先学什么？",
    "expectedDocumentIds": ["替换为实际文档ID"],
    "expectedTools": ["search_knowledge"],
    "expectedAnswerTerms": ["集合"]
  }
]
```

- **可观察成功结果**：能用报告和原文解释一次通过、一次失败、一次未标注；能说出“词出现了不代表回答正确”。如果分数与预期不同，先检查实际文档和报告模式，不直接修改预期来追求满分。
- **常见卡点**：页面接收 JSON 数组，API 请求体才包 `{cases: [...]}`；三个预期数组均保留，空数组表示不评价该项。未标注不是 0 分或 100 分。每批最多 5 条，评测每 IP 每分钟 2 次，多人共用网络可能限流，讲师应分组错开而非反复点击。
- **讲师提示**：先手算“预期 2 个文档、找到 1 个，所以召回为 1/2”。随后再选讲：首个相关文档排第 2，倒数排名为 1/2；MRR 是这些倒数的均值。本项目对多次检索的最终累计证据评分，不能称为每次检索平均。工具召回只检查成功调用的名字；预算耗尽仍失败。离线高分也不代表模型效果。
- **可选挑战**：另准备 2 条从未参与调试的问题作为留出验收集，运行前固定预期，结果差也如实保留。完整定义见 [评测说明](ai-evaluation.md)；目前没有语义忠实度评判器，人工核对仍有价值。

## 第 5 课（选修）：让模型选择工具

- **前置**：第 1–4 课通过；讲师已验证兼容模型服务可达。凭据只由维护者配置在服务端；没有可用模型时可跳过，本期离线核心学习仍完整。
- **目标**：区分规则路由与模型工具调用，知道权限与预算由 Java 服务约束。
- **步骤**：按 [后端配置说明](ai-backend.md) 开启 live，暂不配置 embedding，只问同一个小问题；比较模式、模型步骤、回答和耗时；再问一个与已有资源/竞赛样例相关的问题，观察实际调用的工具。最后只读 `AgentService` 的工具白名单和预算检查。
- **可观察成功结果**：能看到真实模型响应或清晰的上游失败；有模型响应时能指出 `model` 步骤。模型没有选择额外工具也可以如实解释，不能预先保证每次都会选择三种工具。
- **常见卡点**：live 标签表示配置模式，不证明模型网络可用；零 token 也可能是提供方未返回 usage。资料不足不能靠换模型补出协会事实；每次提问独立，没有跨轮记忆。
- **讲师提示**：先问“谁决定调用工具，谁决定允许执行”，再看代码。轨迹是可见执行事件，不是模型内部思维。现场服务故障时回看已标注的历史报告或单元测试，不把它冒充本次 live 成功；费用由服务方产生，课堂只跑少量问题。
- **可选挑战**：阅读 `AgentServiceTest` 的未知工具与预算用例，说明为什么参数校验、白名单和有限调用不能仅靠提示词实现。

## 第 6 课（选修）：同义表达为什么需要另一种检索方式

- **前置**：第 5 课通过；维护者有可用 embedding 模型。使用额外的虚构测试文档，不删除正常业务资料。
- **目标**：把“向量相似度”理解为另一种排序依据，把“RRF”理解为合并排名，区分它们与答案事实核验。
- **步骤**：先保留未启用 embedding 的一组结果；配置 `AI_EMBEDDING_MODEL` 并重新导入这组测试资料；用同一组问题比较引用和分数，再读 `KnowledgeService` 的 cosine 与排名融合。更换模型时重建对应测试文档，不能混用旧模型向量。
- **可观察成功结果**：确认本次启用 embedding 后重新导入的测试文档保存成功，能说明此次对比改了哪个因素，并如实记录“改善、持平或变差”。当前页面不展示每份文档的 embedding 模型，不能仅凭状态栏断言全部资料已向量化。如果原问题已被关键词很好召回，没有提升也是有效结果。
- **常见卡点**：开启配置不会自动给历史文档补向量；状态栏显示配置能力，不证明每条文档已经向量化。重导入会生成新文档 ID，比较评测前须更新对应预期。相似度高不代表事实正确。
- **讲师提示**：先比较两份结果再引出术语；本项目是 MySQL 保存向量、内存逐项评分的小型实现，不是专用向量库的近似最近邻索引。本课不再加入 reranker、图数据库或多 Agent。
- **可选挑战**：为留出问题逐条标注“关键词命中 / 向量补召回 / 两者都失败”，提出一个待验证的改进假设，不直接宣称新策略更好。

## 讲师收尾与学习反馈

每课结束让学习者留下三行记录：“我做了什么 → 看到了什么证据 → 还有什么不能据此推出”。讲师先演示一个例子，再带做一个，最后让学习者独立改一个条件；若最后一步还需要提示，下一次先复做，不继续堆新术语。

核心结课演示只要求：一次离线检索、一次不同身份对照、一次评测结果变化，并能指出对应源码。live 与 embedding 单独记为选修完成度，不以是否购买模型服务判断是否学会。讲师可用自己的措辞复述，只需保持技术含义和证据正确。

本次教材复查发现并调整了三点：旧 Day 标签容易被误读为固定一天完成；长期 roadmap 的“八周第 3–6 周”在本仓库没有对应课表；技术演示把配置、算法和评测连续罗列，缺少每步的成功信号。现在以本页递进活动为授课主线，旧文档作为查阅材料。本安排不代替最新测试记录，也不承诺 PDF/OCR、异步索引、长期记忆、写操作或语义 judge 已实现。
