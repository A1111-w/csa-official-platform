# 开发约束

生效日期：2026-09-16（Asia/Shanghai）。适用于本项目所有人工开发者、主 agent 和子 agent。
章程见 [constitution.md](../.specify/memory/constitution.md)，agent 入口见 [AGENTS.md](../AGENTS.md)。

## 1. 开始前

1. 确认当前需求、作用范围和验收标准，阅读相关源码、配置、测试及文档。
2. 用 `git -C "<项目根目录>" rev-parse --show-toplevel --absolute-git-dir` 核对仓库。
   两个结果必须分别是当前项目及其独立 `.git`，否则停止 Git 写操作。
3. 读取 `git status --short --branch` 和相关 diff，区分已有改动与本次改动。
4. 阅读 [当前状态](project-status.md)和 [CHANGELOG.md](../CHANGELOG.md)。
5. 明确本功能要更新哪些文档；有 Spec Kit 需求时读取对应 spec、plan、tasks。

当前开发位置是 `C:\Users\Administrator\Documents\ChatGPT\计算机协会`。
旧 CSA 目录和 `.migration-backup/` 只作回退证据，不是第二个开发入口。
不修改兄弟项目、全局 Git 配置、旧 worktree，也不擅自配置远程或推送。

## 2. 代码与需求

- 遵循既有 Java 17 / Spring Boot、Next.js / TypeScript 分层，不顺手升级依赖或改写架构。
- 后端业务规则优先放 Service；Controller 负责协议、校验和权限入口，Mapper 负责持久化。
- 前端请求放 `src/services/`，共用 `src/lib/axios.ts`；菜单可见性不能替代后端授权。
- 新功能、缺陷修复、配置、重构、数据库和文档修正都属于需要记录的修改。
- 实现说明以代码和验证为准；需求规格表达约定目标。发现代码违背已确认需求时记录缺陷，
  不得通过篡改需求把错误实现“改成正确”。
- 不把支付、RAG/Agent、多租户等规划写成已实现功能。

## 3. 安全与数据

- 不把 JWT 放回响应体或浏览器持久化存储；保留 HttpOnly Cookie、CSRF 和后端权限校验。
- 保留实时账号状态、权限和会话版本校验；前端资料复用不能充当权限事实来源。
- 记录日志和文档时不得包含真实密码、连接秘密、Token、Cookie、个人数据或数据库备份。
- 测试使用 H2、临时数据或隔离 MySQL/Redis。不得读取旧目录的生产 `.env` 自动启动服务。
- 只新增向前 Flyway migration；不原地改已执行的 V1-V5，不把 `db/schema.sql` 当升级脚本。
- 数据库、上传卷、账号和部署操作必须先确认环境与授权；迁入源码不代表获准操作线上服务。
- 需要删除、清空、强推、覆盖历史时先取得用户明确要求，不能以“整理 Git”为理由执行。

## 4. 每个功能的文档同步

| 变化 | 必须更新的说明 |
| --- | --- |
| 新增功能、入口或完成度 | `README.md`、`docs/module-completeness.md`；必要时更新 `docs/project-status.md` |
| API、字段、错误码、权限 | `docs/api-map.md`；涉及安全边界时更新 `docs/security-design.md` |
| 模块结构、请求链、缓存、任务调度 | `docs/architecture.md`；涉及教学链路时更新 `docs/study-and-demo-guide.md` |
| 数据结构、索引、迁移 | `docs/database.md`、`docs/production-readiness/flyway.md`及相关运行手册 |
| 环境变量、启动或部署 | `docs/local-dev.md`、`docs/deployment.md`、相关环境示例和生产运行手册 |
| 前端路由、会话、验证命令 | `csa-official-frontend/README.md`及相关功能说明 |
| 指标、告警、备份或恢复 | `docs/production-readiness/` 下对应运行文档 |
| 治理规则 | `AGENTS.md`、本文件、项目章程；`agent.md` 仅在导航变化时更新 |
| 每项交付 | `CHANGELOG.md` 中独立记录；使用 [修改记录模板](templates/change-record.md) |

只更新受到影响的文档，不为凑数量修改无关文件。
没有对外行为变化的重构也要在架构或对应维护说明中解释内部变化和兼容性；
纯文档任务更新目标文档和修改记录，不需要虚构业务代码变更。

禁止用“代码自解释”“之后统一补”“另一个 agent 会处理”代替本功能的文档交付。
文档与代码同批提交；若暂不提交，也必须同时保存在当前工作区。

## 5. 修改记录

每个独立功能或修复在 [CHANGELOG.md](../CHANGELOG.md) 的 `[Unreleased]` 下追加独立条目。
推荐编号为 `YYYYMMDD-简短主题`；并行交付使用不同主题避免冲突。
文档对齐这样跨多份文档但目标单一的任务可以作为一项交付。

每条必须写清：

- 日期、编号、执行 agent、相关需求/任务，以及当前状态。
- 为什么修改、实际修改、涉及的代码和文档路径。
- 配置、接口、数据库和兼容性影响；没有变化时明确写“无”。
- 验证命令、执行目录、真实结果、跳过项和原因。
- 风险、遗留工作和非破坏性回退方法。

不能编造提交号、测试结果或历史作者。记录保留历史，错误用新条目更正。
同一提交内不知道自身提交号时使用记录编号即可，不留下假的 commit 占位符。
详细输出可保存在本地忽略目录，但记录须提供可重跑命令和关键结果。

## 6. 验证与完成定义

按风险选择验证：后端改动运行相关 Maven 测试，前端逻辑运行 Vitest，
页面变化补 lint/build 和相应浏览器场景；接口、权限、数据库改动补边界和回归测试。
本项目已有 `tools/check-study-guide-drift.ps1`，只能检查部分静态契约，不能代替业务测试。

每个功能交付前逐项确认：

- [ ] 实现满足约定验收标准，未覆盖用户已有修改。
- [ ] 相关测试已执行，失败已处理；必需验证未通过则仍是未完成。
- [ ] 对应功能文档已同步，路径、命令、权限和配置与源码一致。
- [ ] `CHANGELOG.md` 已追加本功能记录，包含真实验证结果。
- [ ] 相关 Spec Kit 任务状态与实际工作一致（没有该类任务时写不适用）。
- [ ] diff 已审阅，没有秘密、构建缓存、数据库数据或迁移备份。
- [ ] 交付说明列出记录编号、文档位置、验证结果和遗留风险。

未运行、失败、跳过必须分别表达。旧 CI 全绿不证明当前代码已验证；
源码已实现不等于本机服务正在运行，也不等于生产已发布。
这里是开发者和 agent 的强制交付约定，目前没有自动阻止提交的文档 Git hook 或 CI 门禁。

## 7. 多 Agent 协作

1. 主 agent 分配功能、验收标准、允许改动路径和文档责任，避免多人同时覆盖同一文件。
2. 子 agent 交付代码、相关文档修改、独立修改记录和验证证据，不能只交代码。
3. `CHANGELOG.md` 等共享文件由主 agent 协調整合子 agent 的条目，保留原有记录。
4. 主 agent 核对实际 diff 和测试结果后再接受交付；未集成的文档或记录仍属于未完成。
5. 未获用户要求时不新建侧栏任务，不以管理多个 agent 为理由修改其他项目仓库。

## 8. 规则变更

变更本约束须有用户要求或明确确认，同步章程版本及相关 agent 指令并留下记录。
新增业务需求通过项目本地 Spec Kit 技能推进；每个用户故事的 tasks 必须包含验证、
文档更新和修改记录，不把这些工作只留在最终收尾阶段。
